# 06 ｜ レイアウト崩れを検出して直す

**目的**: 「たぶん大丈夫」で出さない。全ページ、はみ出しと重なりがゼロであることを
機械的に確かめ、そのうえで目で見る。

**入力**: 書き込み済みのデッキ
**出力**: 崩れゼロのデッキ

---

## 前提：APIの座標は信用できない

| 信用できないもの | 理由 |
|---|---|
| 表の高さ | `tableRows[].rowHeight` は最小値。セルが折り返すと実際はもっと高い（実例：API上3.12インチ→実際4.30インチ） |
| テキストボックスの高さ | はみ出しても切り詰められず、箱の外に流れて下の要素に重なる |
| 文字数からの見積り | 段落間隔（spaceBelow）が効くため、行数×フォントサイズでは当たらない |

だから検証は**必ずレンダリング結果**（PDF書き出し）で行う。

## プロンプト

```text
レイアウトを検証してください。

1. Drive コネクタでデッキをPDFに書き出す：
   download_file_content(fileId=<デッキID>, exportMimeType="application/pdf")
2. 検証ツールにかける：
   python3 prompts/tools/check_slide_layout.py <書き出しJSON> --from-export \
       --pdf-out deck.pdf --render-dir /tmp/pages
3. NGが出たページを、書き出したPNGで実際に見る。
4. 直したら 1 からやり直す。全ページ ok になるまで繰り返す。

※ Google スライドのサムネイルAPI（lh7-us.googleusercontent.com）は
   ネットワークポリシーで拒否されることがあります。PDF書き出しは通ります。
```

## 崩れの3大原因と、その直し方

| 症状 | 原因 | 直し方 |
|---|---|---|
| タイトルが本文や表に食い込む | タイトルが2行になった（28ptで全角23文字超） | タイトルを短くする。削った読み（例「ヘキサコ」）や但し書きは注記行へ移し、捨てない |
| 表の下の注記が表の最終行に重なる | セルが折り返して表がAPIの行高より高くなった | 列幅を中身の長さに比例させる（均等配分をやめる）。そのうえで注記をレンダリング後の表下端＋0.10インチへ置く |
| 本文の最後の段落が画面外／フッタの裏に消える | 本文プレースホルダの既定の段落間隔が広い | `updateParagraphStyle` で `lineSpacing: 100`、`spaceBelow: 3〜6pt`。フォントを小さくするのは最後の手段 |

フォントを小さくして収める誘惑に注意。14pt→12ptより、段落間隔を詰めるほうが読みやすさを保てる。
投影を前提にすると本文は12pt以上、脚注・出典は9〜10ptが下限。

---

## 受け入れ基準

- [ ] `check_slide_layout.py` が全ページ ok
- [ ] NGだったページをPNGで実際に見た
- [ ] 本文がフッタ帯（y = 5.42）より下に無い
- [ ] 表の下端と次の本文のあいだに 0.10 インチ以上ある

## 実際に起きた失敗

| 起きたこと | 教訓 |
|---|---|
| 文字数から高さを見積もって配置し、全部ずれた | 段落間隔が効くので文字数では当たらない。レンダリングを見る |
| 読みやすさのためフォントを上げたら、4枚で本文が画面外に出た | フォントを上げたら必ず再検証。上げっぱなしにしない |
| 文献スライドを9pt→10ptにしたら、後半の文献と連絡先がまるごと消えていた | 「下が切れている」のは画面を見ないと気づけない |
| 表の下端をAPIの値で計算し、注記を重ねた | 表の高さはレンダリングした罫線の位置から取る |
