# 02 ｜ 読み上げ原稿を先に書く

**目的**: 話す内容を先に全部確定させる。スライドは原稿に従属させる。
先にスライドを作ると、スライドを読み上げるだけの発表になり、時間も読めない。

**入力**: 01 の正典と原典、発表の持ち時間と聴衆
**出力**: `YYYYMMDD_script.md`（話す内容だけ）

---

## プロンプト

```text
発表の読み上げ原稿を書いてください。スライドはまだ作りません。

【書式】
- スライド1枚につき「## ▶ S7」のような見出しを置き、その下に話す文だけを書く。
- 記号：〈間〉＝1秒の沈黙、／＝0.3秒の区切り、**太字**＝声を強める語。
- 段落は空行で分ける。1段落＝ひと息で言い切れる長さ。
- ブロックの切れ目に「# 背景」「# 手法」「# 結果」「# 限界」「# 結論」の見出しを置く。

【中身】
- 話し方はゆっくり。早口で詰め込まない。
- 専門用語は初出で、その分野の専門家でない聴衆にも分かるように説明する。
  （例：HEXACOの6因子、Dark Triadの3特性は、それぞれ1枚かけて説明してよい）
- 学術大会なので、主要な数値には根拠（研究デザイン・N・効果量）を添えて話す。
- 統計手法は「何のためにその手法を使ったか」を日常語で説明する。
  式は出さない。例：「階層的重回帰＝予測の材料を段階的に足して、説明力の変化を見る方法」。
- 冒頭で「本日お伝えすること」を3つ示し、最後にそこへ戻る。
- 想定質疑を別セクションに用意する。

【このファイルに入れないもの】
- 変更履歴、検討の経緯、やらなかったことの説明
- 画面のレイアウト（別ドキュメントにする）
- 自己紹介での動機や思い入れの説明（聴衆の時間を使わない）
- 冒頭の「お伝えしたいこと3つ」への引用（ここは引用なしで言い切る）
```

## 追加で渡すと効くもの

```text
- 自分の研究の限界を、隠さず正面から扱うパートを作ってください。
  発表の山場は結果ではなく「ここまでしか言えない」という線引きです。
- 聴衆の職場（医療・福祉・教育）が当事者になりうることを、
  最初のほうのデータで示してください。「よその業界の話」にしない。
```

---

## 受け入れ基準

- [ ] ファイルに「話す内容」以外が入っていない
- [ ] スライド見出しの番号が連番で、飛びや重複がない
- [ ] 専門用語が初出で説明されている
- [ ] 数値に根拠（デザイン・N・効果量）が添えられている
- [ ] 限界を扱うパートがある
- [ ] 想定質疑がある

## 実際に起きた失敗

| 起きたこと | 教訓 |
|---|---|
| 原稿に変更履歴と検討経緯を混ぜた | 原稿は読み上げるもの。履歴はコミットメッセージに書く |
| 日本人の性格類型の話を入れたら、本筋から浮いた | 面白くても本筋を支えない話は落とす。想定質疑に回す |
| 「残りの8〜9割は性格以外の要因」と書いた | 性格自体に環境の寄与が半分ある。性格と環境は切り分けられない（07参照） |
| Big Five の因子を「情動の安定性」と呼んだ | 正しくは神経症傾向。因子名は原典の表記に合わせる |
| 文を結合して時間を縮めようとした | 〈間〉が1つ消えて／が1つ増えるだけで、0.7秒しか減らない。本当に削るなら語を削る |
